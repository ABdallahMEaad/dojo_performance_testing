# Dojo Web App – Automation & Performance Testing (Selenium + JMeter)

An end-to-end testing project for the **Dojo** web application (`dojo.upexgalaxy.com`) that combines **test automation** and **performance testing**:

1. A **Selenium (Java)** automation script registers 100 new users on the app and generates a CSV of their credentials.
2. An **Apache JMeter** load test then uses those 100 real, registered users to simulate concurrent traffic across login, profile view, shipping form submission, and task creation.

## 📌 Overview

- **Automation:** Selenium WebDriver (Java) — bulk user registration
- **Performance Tool:** Apache JMeter 5.6.3
- **Target:** `https://dojo.upexgalaxy.com`
- **Test Plan file:** `dojo_performance_testing.jmx`
- **Test type:** Load test simulating concurrent, automation-generated registered users performing common in-app actions

## 🧵 Thread Group Configuration

| Setting | Value |
|---|---|
| Threads (users) | 100 |
| Ramp-up period | 20 seconds |
| Loop count | 2 |
| On sample error | Continue |

## 🔄 Test Flow

1. **User Registration (setup phase)** — a separate **Selenium (Java) automation script** registers 100 new users on the app and generates `registered_users.csv` containing their `email` / `password`, used as the data source for the JMeter test below
2. **Login** — `POST /login` using the 100 generated users from `registered_users.csv` (via CSV Data Set Config), plus a cookie manager to persist the session
3. **Extract Auth Token** — a JSON Post-Processor extracts `authToken` (`$.token`) from the login response and reuses it as a Bearer token for later requests
4. **Traffic split (Throughput Controllers)** — after login, each virtual user is routed into one of three weighted paths to simulate realistic mixed traffic:
   - **60%** → **Shipping Information** — `POST /components/forms/shipping-information` using data from `shipping-information.csv`
   - **20%** → **View Profile** — `GET /dashboard/profile`
   - **20%** → **Add New Task** — `POST /dashboard/api/tasks` using data from `create_task.csv`

## 📂 Data Files (CSV Data Set Configs)

| File | Used for | Columns | Source |
|---|---|---|---|
| `registered_users.csv` | Login credentials for the 100 users | `email`, `password` | Generated by a Selenium (Java) automation script that registers the users beforehand  |
| `shipping-information.csv` | Shipping form submission | first name, last name, email, phone, state/governorate, city, zip code, country | Included in this repo |
| `create_task.csv` | Task creation payload | `title`, `descriotian` *(sic)*, `priority` | Included in this repo |

> ⚠️ **Note:** File paths in the `.jmx` are currently hard-coded to local machine paths (e.g. `D:/dojo_performance_testing/...`, `C:/Users/DELL/Downloads/...`). Update the **CSV Data Set Config** elements in JMeter to point to your local copies of these files before running the test.

## ▶️ How to Run

1. Install [Apache JMeter](https://jmeter.apache.org/) (5.6.3 or later recommended)
2. Clone this repo and open `dojo_performance_testing.jmx` in the JMeter GUI, **or** run headless:
   ```bash
   jmeter -n -t dojo_performance_testing.jmx -l result.jtl -e -o report/
   ```
3. Update the CSV Data Set Config paths for `registered_users.csv`, `shipping-information.csv`, and `create_task.csv` to match your local file locations
4. Review results in the **Summary Report** / **Graph Results** listeners, or open the generated HTML dashboard report (`report/index.html` if run headless)
